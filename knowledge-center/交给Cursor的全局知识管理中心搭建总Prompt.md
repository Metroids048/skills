====================
二、总体目标
====================

建立一个中央目录，例如：

D:\AI全局管理中心\

它是本机所有 AI 项目知识的管理端。

每个登记项目都必须拥有自己的本地知识库：

<项目根目录>\项目知识库\

每个项目的知识、会话摘要、决策、错误、修复、测试和内容素材会增量复制到：

D:\AI全局管理中心\项目镜像\<项目名称>\

中央端的稳定用户偏好、收口模式和跨项目经验会同步回各项目，但中央端不得静默覆盖项目事实。

====================
三、权限模型
====================

必须创建两个独立权限域。

A. 全局知识采集器

允许：
- 读取所有登记项目；
- 写中央知识库；
- 写各项目的 项目知识库/、AI原始记录/；
- 安装受控的 .cursor/rules 和 .cursor/commands；
- 在已有 AGENTS.md / CLAUDE.md 中更新明确的托管区块；
- 读取 Git status、diff、log；
- 运行只读或知识整理命令。

禁止：
- 修改业务源码；
- 自动重构项目；
- 读取任何秘密；
- 执行删除、格式化、系统管理、部署、真实资金和不可逆操作；
- 修改权限配置后绕过限制。

B. 当前项目开发 Agent

允许：
- 在当前项目内按项目规则开发；
- 运行真实测试；
- 更新本项目知识库；
- 调用中央同步。

禁止：
- 修改其他项目；
- 直接重写中央主知识库；
- 把敏感记录提交公共 Git。

使用 Cursor CLI 的 allow/deny 权限实现可验证的权限隔离。
Deny 必须优先于 Allow。

不得以“用户要求最大权限”为理由授予整台电脑任意读写和任意 Shell。
