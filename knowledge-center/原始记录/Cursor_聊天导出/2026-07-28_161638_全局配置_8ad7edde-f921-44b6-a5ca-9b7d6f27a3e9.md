## 为什么改了很多回还会出现

**1. 规则修好了，不等于每次任务都会遵守**

你本机已经有一整套门禁：`AGENT_PYTHON`、编码脚本、禁止 `python -c`、禁止 RTK 包 PowerShell cmdlet 等。  
但每个新任务是**新会话模型**，它不会「记住上周踩过坑」；规则是提示，不是硬拦截。所以仍会出现：

- 把 Windows 路径塞进 JS 字符串 → `\U...` 被当成非法转义，命令还没跑就炸  
- PowerShell 正则末尾带 `\` → 枚举日志直接断掉  

这是**助手自己的诊断命令写错了**，不是你的系统又坏了。

**2. 全局 Python 的用途，和「跑项目测试」不是一回事**

全局栈（`AGENT_PYTHON`）装的是：PPT/Word、读中文文件、Office 那一套。  
**默认不装 `pytest`**——项目测试本应走项目自己的环境（你历史记录里也是 `py -3 -m pytest`）。

所以截图里「`AGENT_PYTHON` 是 3.12，没有 pytest」：  
→ 是**用错了运行时**，不是全局栈坏了。  
Agent 却常写成「环境有问题 / 验证卡住」，听起来像又要修一遍 Windows。

**3. 业务已成功，收尾失败被当成「整任务失败」**

例如 Playwright 流程跑完后，清临时目录报 `EPERM`；或缺 .NET SDK 导致某个旁路编译失败。  
主流程其实过了，但报告把「清理/旁路」和「功能失败」捆在一起，你就会感觉「怎么又卡死了」。
