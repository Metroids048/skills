## 错误含义

```
messages[1].role: unknown variant system, expected user or assistant
```

意思是：请求体里 `messages` 数组的第 2 条消息（index=1）带了 `role: "system"`，但你当前接的 DeepSeek 端点 **只接受 `user` 和 `assistant`**，不接受 `system`。

Claude Code 会往 `messages` 里塞 system 消息（系统提示、Agent 定义、会话压缩后的摘要等），DeepSeek 某些端点/网关不支持这种写法，就会直接 400。

## 常见原因

| 原因 | 说明 |
|------|------|
| **接错端点** | 用了 OpenAI 格式的 `/v1/chat/completions`，而不是 CC 需要的 Anthropic 兼容端点 |
| **CC 协议差异** | CC 把 system 放在 `messages[]` 里；DeepSeek 期望 system 在顶层 `system` 字段 |
| **自定义 Agent / 压缩会话** | 使用 `/agents` 或长会话压缩后，更容易注入 `system` role（近期 CC 也有相关 bug 报告） |
| **中间层未做转换** | 若经过 claude-code-router 等代理，可能没把 `system` 转成 DeepSeek 能接受的格式 |

## 错误含义

```
The content[].thinking in the thinking mode must be passed back to the API.
```

DeepSeek 在 **思考模式（Thinking Mode）** 下，如果某轮 assistant 消息里用了 **工具调用（tool calls）**，后续每一轮请求都必须把该轮的 `thinking` 内容原样带回。

Claude Code 的典型流程是：

1. 第一轮：DeepSeek 返回 `thinking` + 工具调用
2. CC 执行工具（读文件、MCP、bash 等）
3. 第二轮：CC 重新组请求，但 **丢掉了上一轮的 `thinking` 块**
4. DeepSeek 校验失败 → 400

CC 几乎总会用工具，所以这个问题在 **第 2 轮及以后** 很常见，不是 Key 或 Base URL 配错。
