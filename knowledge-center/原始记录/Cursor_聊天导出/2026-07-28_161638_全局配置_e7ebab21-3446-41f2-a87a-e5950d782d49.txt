## Summary

Ships a **5-skill maestro bundle** that replaces the 245-line `AGENT_INSTRUCTION_BLOCK` → `MAESTRO.md` injection with installable skills in `~/.claude/skills/maestro-*/` and `~/.codex/skills/maestro-*/`. Adds `--prompt-file` to `maestro handoff`, drops `droid` and `gemini` from `SUPPORTED_AGENTS` (to be re-added later), and closes twelve rounds of fresh-subagent audits against the installed binary so the shipped skills and the CLI agree on every bare form.

Bumps to **0.57.0** (feature).

## What's in the bundle

| Skill | Role |
| --- | --- |
| `maestro-brainstorm` | Migrated from user's `preplan-brainstorm`, chain points at `maestro-plan` |
| `maestro-plan` | Migrated from user's `execution-plan`; persists approved plans to `.maestro/plans/.md`; chain points at `maestro-task` and `maestro-handoff` |
| `maestro-task` | Auto-trigger when `.maestro/` is detected; covers claim → contract → complete, plan-to-batch conversion, recovery verbs |
| `maestro-mission` | Mission / feature / memory system + mission-control TUI reference |
| `maestro-handoff` | paseo-handoff style; uses `maestro handoff --prompt-file` |

`skills/bundled/` is the source of truth; `scripts/sync-bundled-skills.ts` emits `src/infra/domain/bundled-skill-templates.ts` (the embed); `scripts/ci.ts` runs `check:bundled-skills` as a drift gate.

`maestro install` / `maestro agent inject` writes the five skills into each agent's home `~/.claude/skills/` and `~/.codex/skills/`, preserves per-file user edits via a sha256 manifest (`.maestro-bundled.json`), silently removes legacy `MAESTRO.md` and `@MAESTRO.md` references, and sweeps stale `maestro-*/` skill dirs that still carry the maestro-managed marker. `maestro agent remove` is the inverse.

## CLI adjustments to serve the skill workflow

### Handoff

- `maestro handoff --prompt-file ` — positional ` ` becomes optional; brief file is persisted verbatim to `.maestro/launches/ /prompt.md` (wrapped with a minimal \"## Handoff Startup\" pickup preamble for the receiving agent). Validates non-existent / empty / directory paths with structured `MaestroError`s.
- \`status: \"consumed\"\` on pickup; `handoff show --json` normalizes legacy pre-0.56 packets (`consumedAt` set but `status: \"launched\"`) at read time.
- Pickup identity falls back to `basename(homedir())` when `USER`/`USERNAME` are unset (Bun's `userInfo().username` returns the literal `\"unknown\"` in that case, so the homedir fallback yields a real user name on every platform).
- `handoff pickup` resolves from the packet's own `agent` field when no session is detected, so the bare form just works.

### Task

- **Hard Rule 1** enforced at `task update --status in_progress` (was only on `task next` and `task claim`). `--force` bypasses the busy-session check.
- **Hard Rule 2**: completion without `--reason` is rejected with a hint.
- `task contract new | edit | amend` auto-detect piped stdin via `fstatSync(0)` (FIFO or regular file). Works under shells that export `$EDITOR` / `$VISUAL` (the previous condition skipped stdin whenever an editor was ambient, leading to a hang).
- `task plan` idempotent replay reports `[ok] N task(s) already present (replayed)` instead of `created`.
- `task contract new | edit | amend | criteria *` share the per-user synthesized session fallback, so bare invocations work without spelling `--session`.
- `task contract reopen` on a non-completed task hints at both `task update` and `contract amend` / `criteria *`.
- `task unblock ` now succeeds (completed blocker stays frozen; blocked side's stale `blockedBy` entry is cleared).
- `normalizeGraph` no longer resurrects graph edges from completed tasks on read.
- `task show ` text view filters resolved (completed) blockers from the \"Blocked by\" line; `--json` preserves the raw graph for agents.

### Agent surface

- `SUPPORTED_AGENTS` now contains only `claude-code` and `codex`. `droid` / `gemini` will be re-added once their CLIs expose skill support.
- `AGENT_INSTRUCTION_BLOCK` deleted; `PROJECT_BOOTSTRAP_TEMPLATES` (per-project `.maestro/AGENTS.md` bootstrap) untouched.

## Doctrine

\`CLAUDE.md\` now codifies two rules the maintainers fought out across this branch:

1. **The skill bundle is the spec.** When the CLI diverges from a skill, fix the CLI. Never quietly edit a skill to match surprising CLI behavior.
2. **Always release + link locally for testing.** `bun run release:local` rebuilds `dist/maestro` *and* installs it on `PATH`; verifying only `./dist/maestro` misses install-path regressions.
