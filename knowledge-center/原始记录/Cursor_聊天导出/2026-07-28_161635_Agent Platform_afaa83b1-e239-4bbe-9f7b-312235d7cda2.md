## 原因说明

### 1. 不能「嵌进」Cursor 自带左侧对话

Cursor 左侧/右侧的 **Agent 对话**（Composer / Chat）是 Cursor 内置面板。  
**Claude Code 是独立扩展**，没有接口可以挂进那块区域，也不能和 Cursor Chat 合并成一个固定侧栏。

所以「固定到左边对话区」在现状下 **做不到**——只能放在 Activity Bar 侧栏视图，或编辑器分栏里。

### 2. Cursor 3.0+ 改了侧栏架构（Glass / Agents Window）

Cursor 3.0 起用 **Glass 布局**，原来的 **右侧辅助栏（Auxiliary Bar）** 被 Agents Window 取代。  
Claude Code、Codex 等扩展 **不能再像 VS Code 那样稳定挂在右侧第二侧栏**。

官方说明：扩展应放在 **左侧 Activity Bar**，或 **编辑器分组**（拖成右侧分栏）。  
详见论坛：[Extension no longer supported in second sidebar](https://forum.cursor.com/t/extension-no-longer-supported-in-second-sidebar/156491)

### 3. 扩展误判 Cursor「支持第二侧栏」→ 图标消失

Claude Code 会检测宿主是否支持 `AuxiliaryBar`。在 Cursor 里检测结果不稳定，有时会：

- 认为支持第二侧栏 → **隐藏左侧 Activity Bar 图标**
- 实际打开时又失败 → 只能反复用 `Ctrl+Shift+P` 执行 `Claude Code: Open` / `Open in Sidebar`

这是上游已知问题：[anthropics/claude-code#31375](https://github.com/anthropics/claude-code/issues/31375)

### 4. 布局被重置

更新 Cursor、重载窗口、`View: Reset View Locations` 后，侧栏位置可能丢失，看起来就像「每次都要重新打开」。

## 3. 为什么你觉得「还是同一个 HCL API」，列表却空了？

这里有个容易误导人的点：

- 你现在登录用的是 **HCL 的 API Key**（`auth.json` 里是 `apikey` + hctopup）
- 当前配置也是 **custom → `https://ai.hctopup.com/v1`**

但 **Skills 那场长会话在元数据里被标成了 `deepseek`**，不是 `custom`：

```json
"model_provider": "deepseek"   // 会话 019e6c68 创建时打的标签
```

而同一场对话里，Codex 读到的 `config.toml` 其实已经是 **custom + hctopup**。也就是说：

> **底层可能一直在走 HCL，但会话列表按 `model_provider` 标签分桶；重启后界面很可能只显示当前桶（custom）里的会话。**

所以你会感觉：「我没换 API，怎么历史没了？」——**人没换，但 Codex 给旧会话贴的标签和重启后的「当前线路」不一致，列表就被藏起来了。**

另外还有一层：

- 侧边栏用的 `session_index.jsonl` **只有 6 条**
- 数据库里有 **27 条**  
→ 索引文件在重启/卡死后**没写全**，列表本身就不完整。

## 4. 这不是「换账号」，更像是这三件事叠在一起

1. **长任务卡死 → 强制重启**（索引/界面状态容易坏）  
2. **重启后要重新用 API Key 登录**（会话列表刷新，按 provider 过滤）  
3. **旧会话被标成 `deepseek`，新会话是 `custom`**（同一家网关，标签不同 → UI 不显示旧的）

这是 **Codex 桌面端会话管理的缺陷**，不是你以为的「连本地历史都不存」。
