推荐架构

不要分别维护三套完全不同的规则。最佳结构是：

全局个人规则
    ↓
项目根目录 AGENTS.md（共同事实来源）
    ↓
工具专用补丁
    ├── Cursor .cursor/rules/*.mdc
    └── Claude CLAUDE.md + .claude/rules/
    ↓
verify-work Skill
    ↓
测试、CI、Hooks、权限等硬性约束

Codex 原生读取全局和项目级 AGENTS.md；Cursor 支持全局 User Rules、项目 .cursor/rules 和 AGENTS.md；Claude Code 虽然不直接读取 AGENTS.md，但可以通过项目 CLAUDE.md 中的 @AGENTS.md 导入，从而避免三份项目规范逐渐不一致。

项目规则

<项目根目录>/AGENTS.md

AGENTS.md

AGENT_LESSONS.md 应该记录什么

只记录长期有效且经过验证的内容：

真实可用的构建和测试命令
项目特殊架构约束
Agent 重复出现两次以上的错误
已证实的故障根因与修复方法

不要记录：

临时任务进度
一次性日志
未经验证的猜测
用户隐私或密钥
某次会话的全部上下文

Claude Code 的 auto memory 适合记录构建命令、调试经验和项目模式；其 MEMORY.md 启动时只加载前 200 行或 25KB，因此应该保持为索引，而不是不断堆积所有历史内容。它也只是上下文，不是硬性执行机制。

六、最重要的使用原则

这套配置没有强迫每个小任务都写长计划：

单文件小修改：直接检查、修改、运行针对性测试。
Bug：先复现，再加回归测试和修复。
多文件或架构任务：形成里程碑和验收条件。
分析、研究、评审任务：禁止擅自实施。
重要功能：最后使用独立上下文评审。
真实资金、生产部署、破坏性数据库操作：必须人工确认。
同一失败连续两次没有进展：停止重复方案。
所有“完成”声明必须附带真实命令和结果。

提示词只能影响 Agent 行为，不能保证绝对执行。真正不能违反的规则，例如禁止读取 .env、阻止危险命令、结束前运行测试，应继续通过 Hooks、权限、测试和 CI 强制执行。Claude 官方明确区分了行为指导和确定性 Hooks；Cursor 也支持在停止阶段触发验证循环。
