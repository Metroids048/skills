# AI 求职台

面向应届、实习和校招用户的本地优先 Web MVP。当前产品主线收敛为：

**导入/确认简历与 JD → 开启实时面试助手 → 识别问题 → 生成提词卡 → 保存记录 → 复盘改进**

产品参考 Final Round AI、LockedIn AI、Interviews.chat、OfferGoose 的实时转写、即时建议、JD/简历个性化、会后反馈闭环，但不做隐蔽代答、不捕获系统音频、不把本地规则伪装成模型成功。

## 核心体验

* **实时助手驾驶舱**：首页第一动作是听取或输入面试官问题，生成可讲的回答框架，而不是铺满 JD 诊断工作台。
* **上下文资料**：JD 与岗位卡、问题库、简历证据都收进二级区域，作为实时助手和模拟练习的上下文底座。
* **提词卡片**：输出回答策略、开场句、要点、可引用证据、风险提醒和可能追问，不输出自动代答逐字稿。
* **诚实模型状态**：提词卡和模拟追问展示 `模型生成` 或 `本地练习`，后端未连接、模型失败、JSON 不合规时明确标记 fallback 原因。
* **模拟练习**：作为实时助手前的预演模式，题序来自 JD、问题意图和简历证据排序；本地兜底时显示本地练习模式。
* **记录复盘**：实时助手和模拟练习都会保存记录，报告绑定当次 transcript、题词卡、证据命中和表达指标。

## 前端结构

`App.tsx` 只保留全局状态、导航和路由编排；主要页面拆到组件目录：

* `src/components/live.tsx`：实时助手驾驶舱、实时题词卡、模拟面试间。
* `src/components/context.tsx`：上下文资料、简历证据、问题库。
* `src/components/home.tsx`：JD 对话收集、岗位卡、面试配置弹窗。
* `src/components/records.tsx`：记录列表、复盘报告、账户与数据导入导出。
* `src/components/shared.tsx`：共享 UI、配置类型、辅助函数。

## 数据模型

`AppState` 仍是候选人档案加多 JD 容器：

* `profile: CandidateProfile`
* `positions: Position[]`
* `activePositionId: string`
* `interviewRecords: InterviewRecord[]`
* `activeRecordId: string`
* `aiMode: boolean`

关键接口：

* `AnswerCueCard`：一次实时问题或模拟问题生成的提词卡。
* `InterviewRecord.mode`：区分 `live` 实时助手记录和 `mock` 模拟练习记录。
* `AiRunMeta`：包含 `backendStatus`、`fallbackReason`、`evidenceTrace`、`latencyMs`。

## AI 与语音边界

语音能力使用浏览器麦克风和 Web Speech API；不捕获桌面系统音频，不抓会议软件系统声。浏览器不支持或授权失败时，实时助手和模拟练习都会降级为文字输入。

Web Speech 转写保留 interim、final、editable 文本分离；停止听取不会清空已识别文本，只有用户点击清空/重录才清空。

Assistant: **8MB 本身大概率不是问题**——这是 Git 仓库的正常体积。真正需要核对的是：你下的是不是「完整可运行环境」，以及 `main` / `work` 两个分支是否已经分叉。

---

## 1. 8MB 是 Git 源码体积，不是「整台开发机文件夹」体积

当前仓库 Git 打包大小约 **7.94 MiB**，和你说的大致 8MB 一致。

Git **故意不上传**这些内容（见 `.gitignore`）：

| 被排除的内容 | 典型体积 | 说明 |
|---|---|---|
| `node_modules/` | 200MB～500MB+ | 依赖包，clone 后需 `npm install` |
| `dist/` | 几 MB～几十 MB | 构建产物 |
| `.env` | 很小但含密钥 | 本地 API Key，不能进仓库 |
| `.data/*.sqlite` | 可变 | 本地数据库 |
| 各类 `.log` | 可变 | 运行日志 |

所以：

- **GitHub 下载 ≈ 8MB** → 正常（只有源码 + 文档 + 图片）
- **能跑起来的完整项目** → clone 后还要 `npm install`，通常 **200MB 以上**

如果你昨天在另一台设备上看到的文件夹是几百 MB，多半是因为那里有 `node_modules`，不是 Git 漏传了。

---

## 2. 更关键的问题：`main` 和 `work` 已经分叉

远程有两个不同版本的代码：

| 分支 | 最新提交 | 独有内容 |
|---|---|---|
| **`main`**（GitHub 默认分支） | `5a0395e feat: update full project changes` | 验收文档、`positions` 相关测试等 |
| **`work`** | `230938c 前端优化` → `db6c517 AI功能完善` | `conversation.tsx`、`jobs.tsx`、`mock-setup.tsx`、`vibe-coding-0to1-handbook.md`、`全局配置/` 等 |

两个分支从 `223e412 sync 2026-06-23` 之后**各自往前走，没有合并**。

- GitHub 网页默认展示的是 **`main`**
- 你本机 `program1-main` 当前在 **`work`** 分支

很可能昨天在另一台设备推的是其中一个分支，今天下载的是另一个，所以会觉得「代码对不上 / 少了东西」。

---


## 4. 怎么判断你缺的是哪一种

**情况 A：只是觉得太小，跑不起来**

在新下载的目录执行：

```bash

npm run verify
```

能过 verify，说明源码是完整的，之前只是缺依赖。

**情况 B：代码内容和昨天那台设备不一致**

先确认昨天推的是哪个分支：

```bash
git fetch origin
git log --oneline origin/main -3
git log --oneline origin/work -3
```

- 要 **`main` 那套**：`git checkout main`
- 要 **`work` 那套（前端优化 + AI 完善）**：`git checkout work`

**情况 C：想把两套合并成一条线**

需要在其中一台设备上手动 merge，再 push（不能指望「下载 zip」自动合并两个分支）。

---

## 5. 快速自检清单

在新下载的目录里：

2. 没有 `node_modules` — 正常，执行 `npm install`
3. 没有 `.env` — 正常，从 `.env.example` 复制并填 Key
4. 没有 `prototype/` — 这个 React 项目本来就没有 prototype 目录；若你合并的是「prototype + 正式 app」两份代码，prototype 可能从未进 Git
