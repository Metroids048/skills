# Cursor 全局知识管理中心：架构、权限与同步方案

> 版本：V1  
> 日期：2026-07-28  
> 适用环境：Windows 本机，Cursor 为主要搭建工具，同时兼容 Codex、Claude Code  
> 建议中央目录：`D:\AI全局管理中心\`

---

## 一、结论

不要把“最大权限”理解为：

- 允许 Agent 读取整块系统盘；
- 允许任意 PowerShell、删除、注册表和系统命令；
- 允许自动上传、部署、交易、付款和推送所有仓库；
- 允许把所有原始聊天、客户文档和密钥混进一个知识库。

推荐采用：

> **最大可用范围＋最小危险权限＋全量可审计记录。**

系统分为两个权限域。

### 1. 全局知识采集器

可以：

- 读取所有登记项目；
- 读取 Git 状态、diff、commit、测试记录和项目文档；
- 创建和更新各项目的 `项目知识库/`；
- 写入中央管理端；
- 安装或更新受控的 Cursor 规则、Commands 和知识同步配置；
- 生成项目摘要、会话胶囊、经验、决策和内容素材。

不可以：

- 修改各项目业务源码；
- 读取 `.env`、密钥、钱包、浏览器数据和系统目录；
- 执行生产部署、真实交易、付款和破坏性命令；
- 自动覆盖已有 `AGENTS.md`、`CLAUDE.md`；
- 自动推送公共仓库。

### 2. 项目开发 Agent

可以：

- 在当前项目内完整读写；
- 运行该项目真实需要的开发和测试命令；
- 读取本项目 `项目知识库/`；
- 任务结束后调用同步工具。

不可以：

- 任意修改其他项目；
- 直接重写中央主知识库；
- 将敏感原始记录提交到公开 Git；
- 绕过项目自己的测试、Hooks 和安全边界。

## 二、现实能力边界

### 可以实现

- 自动发现指定目录下的 Git 项目；
- 给每个项目安装统一的规则和归档命令；
- 记录项目文件变化、Git diff、commit、测试、命令和产物；
- 对 Cursor CLI 发起的任务，记录用户 Prompt、Agent 事件、工具调用和最终输出；
- 在每次任务结束后生成结构化会话记录；
- 把项目知识复制到中央管理端；
- 从中央端向项目同步稳定的用户偏好和跨项目经验；
- 每周、每月自动生成汇总与视频选题。

### 不能承诺完全自动实现

- 无条件截获 Cursor 图形界面中每一条历史聊天；
- 自动读取 ChatGPT、Claude 网页版等其他应用的所有私有聊天；
- 获取模型的私有思维过程；
- 在没有导出或适配器时还原所有旧对话；
- 保证第三方插件升级后内部数据库格式不变化。

### 最可靠的记录方式

1. **Cursor CLI 任务**
   - 通过统一包装脚本启动；
   - 使用 `stream-json` 保存结构化事件；
   - 自动生成原始事件和摘要。

2. **Cursor 图形界面任务**
   - 使用 `/开始任务记录`；
   - 正常完成工作；
   - 使用 `/结束并归档`；
   - 对特别重要的完整对话，再使用 Cursor 内置“导出聊天为 Markdown”。

3. **其他 AI 对话工具**
   - 导出 Markdown / JSON；
   - 放入中央 `待整理输入/`；
   - 由导入器生成标准会话胶囊。

## 七、双向同步模型

### 项目 → 中央

自动同步：

- 项目总览；
- 当前状态；
- 新决策；
- 新经验；
- 错误与根因；
- 已验证解决方案；
- 会话胶囊；
- 可公开视频素材；
- Git commit、测试和验证摘要。

默认不同步：

- `.env`；
- Cookie；
- 密钥；
- 客户原始文件；
- 完整数据库；
- 交易账号和钱包；
- 未脱敏个人信息；
- 大量构建产物；
- 不必要的完整代码副本。

### 中央 → 项目

只同步：

- 用户稳定偏好摘要；
- 收口模式；
- 跨项目通用 Agent 经验；
- 与当前项目有关的历史教训；
- 统一会话记录规范；
- 当前项目在中央登记的最新状态摘要。

中央端不得直接覆盖项目事实。发生冲突时：

1. 生成待确认补丁；
2. 保留两条记录；
3. 标记 `CONFLICTED`；
4. 由用户或有真实证据的 Agent 决定。

## 八、权限设计

## 8.1 两个 Cursor 权限配置

### A. 全局知识采集配置

允许：

- 读取登记项目；
- 写中央目录；
- 写每个项目的：
  - `项目知识库/**`
  - `AI原始记录/**`
  - `.cursor/rules/全局知识与会话归档.mdc`
  - `.cursor/commands/**`
  - 受控的 `AGENTS.md` / `CLAUDE.md` 管理区块。

拒绝：

- 项目源码写入；
- `.env`、密钥和钱包读取；
- 系统目录；
- 删除和格式化磁盘；
- 生产部署和真实资金操作。

### B. 当前项目开发配置

允许：

- 当前项目全量读写；
- 项目真实开发命令；
- 写本项目知识库；
- 调用中央同步脚本。

拒绝：

- 其他项目源码写入；
- 中央主知识库直接重写；
- 高风险操作。

## 九、会话记录方案

## 9.1 Cursor CLI：高完整度

统一通过：

```powershell
python "D:\AI全局管理中心\工具\开始AI任务.py" `
  --项目 "自动量化交易系统" `
  --工具 "CursorCLI" `
  --任务 "修复自动开仓阻塞"
```

包装器负责：

1. 保存用户输入；
2. 启动 `cursor-agent -p --force --output-format stream-json`；
3. 保存原始 JSONL；
4. 提取：
   - assistant 输出；
   - tool calls；
   - 文件操作；
   - 命令；
   - 最终状态；
5. 运行 Git 和测试收集；
6. 调用会话归档 Prompt；
7. 同步至中央目录。

## 9.2 Cursor 图形界面：中等完整度

开始：

```text
/开始任务记录
```

结束：

```text
/结束并归档
```

系统记录：

- 任务目标；
- 可见对话摘要；
- Git diff；
- 文件修改；
- 命令和测试；
- Agent 最终输出；
- 用户纠正；
- 决策和经验。

对需要保留完整原文的会话，用户手工“导出聊天为 Markdown”到：

```text
D:\AI全局管理中心\待整理输入\
```

## 9.3 Hooks 的职责

Hooks 用于记录和约束：

- 文件读取；
- 文件修改；
- Shell 命令；
- Agent 停止；
- 验证脚本；
- 隐私拦截。

Hooks 不作为“完整聊天原文采集”的唯一依赖。

## 十、隐私和数据分层

| 级别 | 示例 | 同步方式 |
|---|---|---|
| PUBLIC_SAFE | 脱敏后的项目经验、视频选题 | 可进入内容素材库 |
| PRIVATE | 一般项目状态、个人偏好 | 私有中央仓库 |
| SENSITIVE | 客户、法律、交易、身份、公司材料 | 本地加密或受限目录 |
| SECRET | 密钥、Cookie、Token、钱包、私钥 | 永不进入知识库 |

中央目录建议：

- 使用私有 Git；
- 启用磁盘加密；
- 敏感目录不推远程；
- 每次提交前运行 secret scan；
- 原始聊天和摘要分开；
- 默认模型只读取摘要，不自动加载原始记录。

- [ ] 每个项目生成中文 `项目知识库/`；
- [ ] 每个项目安装 Cursor Rules 和 Commands；
- [ ] 不覆盖已有项目规则；
- [ ] 能对 CLI 任务保存用户输入、事件和 AI 输出；
- [ ] GUI 会话能通过开始/结束命令生成摘要；
- [ ] 能导入手工导出的完整聊天；
- [ ] 能记录 Git status、diff、commit；
- [ ] 能记录真实命令、测试和产物；
- [ ] 项目知识能增量同步到中央；
