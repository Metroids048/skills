# 1. 用户核心画像

## 1.1 职业与能力背景

- `[CONFIRMED]` 用户有全职工作。
- `[CONFIRMED]` 用户自我定位为 **AI 产品经理**。
- `[CONFIRMED]` 用户不具备传统编程基础，自述“完全不懂代码”或不以手写代码为主要能力。
- `[CONFIRMED]` 用户高频使用 Cursor、Claude Code、Codex。
- `[CONFIRMED]` 用户能够通过 Agent 推动复杂项目、整理需求、设计 Prompt、审查结果和定义验收标准。
- `[CONFIRMED]` 用户自述没有深厚的垂直行业经验或明显的专家型流量标签。
- `[INFERRED]` 用户正在形成的核心能力不是“亲自编程”，而是：
  - 将模糊目标拆成 Agent 可执行任务；
  - 管理多个 Agent 和多轮修改；
  - 识别 Agent 虚假完成、无限分析和范围膨胀；
  - 通过测试、证据和业务链路进行验收；
  - 把需求、工程和产品判断连接起来。

## 1.2 时间、收入与生活约束

- `[CONFIRMED]` 用户有主业，副业可投入的时间和精力有限。
- `[CONFIRMED]` 用户希望寻找副业、兼职和可逐渐形成被动收入的模式。
- `[CONFIRMED]` 用户更偏好可自动化、时间可控、搭建后维护成本较低、能持续积累资产的模式。
- `[CONFIRMED]` 用户当前认为自动交易和 Alpha 自动化在真正跑通后更接近该目标。
- `[CONFIRMED]` 用户对成本较敏感，特别关注 Agent token、订阅、中转站、网络工具和长期烧钱问题。

## 1.3 沟通偏好

- `[CONFIRMED]` 默认使用中文沟通。
- `[CONFIRMED]` 代码、命令、日志、标识符和项目原有术语保持原语言。
- `[CONFIRMED]` 不喜欢：
  - 重复询问已经回答过的问题；
  - 无边界全面分析；
  - 每次修改后继续找大量非阻塞问题；
  - 为“更优雅”而重构；
  - 模糊地说“应该可以”“理论上通过”；
  - Agent 声称完成但没有真实证据；
  - 项目永远分析、永远改不完。
- `[CONFIRMED]` 偏好具体、可执行、直接能甩给 Codex/Claude Code 的 Prompt 和 Markdown。
- `[CONFIRMED]` 复杂任务可以分模块，但每个模块必须能独立验收并收口。
