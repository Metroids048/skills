## 0. 覆盖范围与可信度

### 0.1 本版使用的资料

本版基于截至 **2026-07-28** 可访问的：

- 当前 ChatGPT 对话；
- 近期可检索的账号对话和个人上下文；

本文件不能保证覆盖：

- 已删除、未索引、不可访问或未同步的历史对话；
- Cursor、Codex、Claude Code 中尚未导出的完整聊天记录；
- 用户没有提供给 AI 的线下行为和决策；
- 项目仓库中未被读取的文件、分支和日志。

因此，本文件不是“账号全部历史的绝对完整副本”，而是当前能够可靠整理出的第一版主知识库。

# 2. 用户长期工作规则：收口模式

## 2.1 默认目标

对于代码、项目和 Agent 任务，默认采用“收口模式”：

1. 锁定唯一目标；
2. 写明可观察的验收标准；
3. 只处理阻塞目标的问题；
4. 不主动扩展到全面重构、架构改写、代码美化和非阻塞优化；
5. 先修根因，不做掩盖症状的补丁；
6. 完成后停止，不继续无边界寻找更多问题。

## 2.2 优先处理的问题

只有以下问题通常可进入当前任务：

- 阻塞端到端业务链路；
- 导致数据、状态、资金或仓位错误；
- 幽灵单、重复单、错误方向；
- 真实执行与本地状态不一致；
- 明确的安全风险；
- 验收测试失败；
- 直接影响用户当前唯一目标的问题。

## 2.3 默认禁止事项

未经用户明确授权，不得：

- 扩大需求范围；
- 全仓重构；
- 更换框架或包管理器；
- 批量升级依赖；
- 全仓格式化；
- 随意改变公共接口；
- 删除、跳过、弱化有效测试；
- 伪造命令、日志、测试结果、平台响应或性能数据；
- 操作真实资金；
- 启用 Mainnet；
- 生产部署；
- 读取、输出或提交密钥、Token、Cookie、私钥和 `.env`；
- 执行破坏性数据库或 Git 操作；
- 自动发布自媒体内容。

## 2.4 验收规则

- 行为验证优先于“看起来代码正确”。
- 缺陷修复应尽量先复现，并补回归测试。
- 完成前运行项目真实存在的针对性测试。
- 按项目要求运行适用的 lint、typecheck、build、integration/E2E 和业务验证。
- 没有执行的检查必须标注“未验证”，不能写成通过。
- 较大修改应由新的上下文或独立只读 Reviewer 复核。
- 确定性测试失败优先于模型意见。
- 同一检查最多自动修复 3 次。
- 连续两次没有实质进展，应停止重复方案，回到根因和边界重新分析。
- 最终报告必须包含：状态、改动、原因、影响文件、实际命令与结果、验收映射、未验证项、限制、风险和最小下一步。

## 5.1 项目 A：7×24 小时自动量化交易系统

### 基本信息

- 状态：`[OPEN][ACTIVE]`
- 核心资产：BTC / ETH
- 当前环境：Binance Demo / USDT-M Testnet / 模拟环境
- 明确非目标：Mainnet、新增大量币种、动态仓位、动态杠杆、在主链路没跑通前继续堆复杂策略。

### 用户目标

- 7×24 自动运行；
- 根据真实市场数据自然产生交易机会；
- 跑通自动开仓、保护、自然退出、止损止盈和自动平仓；
- 能对收益率和风险进行真实验证；
- AI 参与研究和上下文分析，但不能自由决定关键订单数值。

### 关键硬约束

- 只交易 BTC / ETH。
- 仓位和杠杆使用固定设置。
- AI 不直接决定交易所订单数量、任意入场价、任意止损价和任意止盈价。
- 精确订单参数由确定性程序根据最新交易所数据计算。
- Testnet 与 Local Paper 必须明确隔离。
- 不允许 Synthetic Local Fill 冒充交易所成交。
- 保护失败需 fail-closed，并保留紧急 ReduceOnly 退出能力。
- 新开仓阻断不能阻止已有仓位减风险退出。

### 已发现的关键问题

- `[CONFIRMED]` 长期不自动开单。
- `[CONFIRMED]` 本地 paper 出现幽灵单。
- `[CONFIRMED]` 前端多处占位符没有与后端和交易所实时数据打通。
- `[CONFIRMED]` AI API 使用量曾为 0，说明 AI 分析链没有真正执行。
- `[CONFIRMED]` 自动开仓曾在 `gateway.submit_order()` 前因缺少 `market_rules_snapshot` fail-closed。
- `[CONFIRMED]` 自动平仓曾通过 `run_id + symbol` 错误继承历史 protection，出现 ETH 误平仓风险。
- `[CONFIRMED]` “没有交易”曾无法区分无信号、市场状态不匹配、MetaLabel 拒绝、风险拒绝、AI 拒绝、数据过期或执行失败。
- `[CONFIRMED]` 回放和实时执行存在价格、时间和成交语义偏差。
- `[CONFIRMED]` 现有候选策略高度共享趋势、ADX 等信息，策略多样性不足。
- `[CONFIRMED]` 固定 2R 退出忽视不同策略收益分布。
- `[CONFIRMED]` 缺少市场结构、成交量、订单流和衍生品数据。

- 冻结旧 `paper_*` 混合链路。
- 使用独立 `services/automated_trading` 垂直模块。
- Testnet 与 Local Paper 互斥。

## 5.2 项目 B：WorldQuant Alpha 自动生成、测试与提交

### 状态

- 状态：`[OPEN][ACTIVE]`
- `[STALE]` 2026-07-23 时主设备项目无法正常运行，需要更新最新状态。

### 用户目标

- `run_pipeline_loop.py` 真正永久循环运行；
- 普通模拟、网络、认证、返回码错误不能永久终止主循环；
- 使用账号+密码登录，Session 过期后自动重新登录；
- 不要求用户手工提供 Cookie；
- 自动生成、测试、生成模板描述和提交 Alpha；
- 只重试“唯一阻塞是描述缺失”的历史 `UNSUBMITTED` Alpha；
- 不盲目重提所有失败 Alpha。

### 已知问题

- 新生成 Alpha 高度依赖 `group_rank`。
- 高自相关。
- 低 Sharpe / 低指标。
- 大量 Alpha 因平台模板描述缺失无法提交。
- 用户不能逐条手工填写描述。
- 主循环修改后出现 blocked / 无法继续。
- Cookie 曾短暂可用，但整体链路不稳定。

### 提交边界

只有其他基础检查、Self-correlation 和 Production correlation 已明确通过，且唯一阻塞项是描述缺失或格式无效，才适合自动补描述并重提。

Base gate、自相关、生产相关、指标或样本外可信度失败时，不得因为补描述而重提。

## 5.3 项目 C：Agent Video Studio

### 状态

- `[USER_REPORTED]` 用户已使用 Claude Code 完成项目开发和验收测试。
- 独立状态：尚未由本知识库重新运行仓库命令验证。
- 当前阶段：从“软件工程验证”进入“真实内容生产验证”。

### 项目目标

接收文本、图片、录屏、音频、参考视频、网页/GitHub 链接和零散想法，输出参考分析、内容简报、脚本、分镜、素材缺口、字幕、时间线、带字幕/无字幕粗稿、HyperFrames 动效、QA、可编辑交付包和抖音/小红书发布文案。

### 核心定位

- 通用短视频结构分析与粗剪生产系统。
- 不是无人审核的账号托管系统。
- 用户完成最后约 10%—30% 的人工编辑、审美和发布。
- 参考视频用于学习结构、节奏、字幕、镜头语言和动效，不等于复制原文案、原配音和受保护画面。

### 生产模式

1. `REFERENCE_CLONE`：内部学习和形式验证，不默认公开发布。
2. `REFERENCE_ADAPT`：默认公开模式，保留结构与节奏，替换文案、观点、数据、案例、配音和素材。
3. `ORIGINAL`：使用自有模板，后续逐渐积累。

### 技术与配置

- Git、Node.js 22+、Python 3.11+、FFmpeg/FFprobe、HyperFrames。
- 项目自有 Skills 唯一编辑源：`skills-src/`。
- 同步至 `.claude/skills/` 和 `.agents/skills/`。
- 业务唯一 CLI：`python -m avs`。
- npm 只做便捷包装。
- HyperFrames 负责动效片段，FFmpeg 负责基础合成。
- `timeline.json` 为共享中间协议。
- 原始素材不可覆盖、移动和修改。
- Codex HyperFrames 插件是增强，不是核心硬依赖。

### V1 非目标

自动发布、自动登录平台、自动评论私信、数字人、声音克隆、Remotion 主渲染器、云渲染、多账号矩阵、剪映草稿核心依赖。

- 重复信息；
- 旧结论但没有标记过期；
- 密钥、Token、Cookie、私钥、完整 `.env`；
- 未脱敏客户数据；
- 未确认的法律结论；
- 模型私有思维过程。

## 11.3 冲突处理

1. 不静默覆盖；
2. 标记旧记录为 `[STALE]`；
3. 写明新证据、日期和来源；
4. 只有有证据的新记录才能升级为 `[CONFIRMED]`；
5. 用户明确纠正优先于旧推断；
6. 测试和真实外部结果优先于 Agent 自述。

## 11.4 公开内容提取

进入公开视频前检查：客户和项目隐私、身份和账号、交易和法律信息、投资建议、收益承诺、版权与许可证、未验证结论和 AI 生成标识。
