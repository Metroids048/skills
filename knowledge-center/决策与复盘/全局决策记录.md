### ADR-G001：Global memory hub（2026-06-01）

- **决策**：跨项目 PDCA 主记忆放在 `~/.ai-workspace/memory/`；项目仅可选薄层 `project-memory.md`。
- **后果**：新项目零记忆文件即可开工；团队仓可加 overlay。

### ADR-G002：Skills single source（2026-06-01）

- **决策**：`~/.cursor/skills/` 为规范源；Claude skills 用 junction；hooks 扫全局、UserPromptSubmit 仅 Top 8。
- **后果**：Agent Platform 仓是 skills **源**，不是运行时依赖。

### ADR-G003：最大权限 ≠ 破坏性范围（2026-06-03）

- **背景**：用户给「最大权限」修 Codex 401 时，Agent 未经授权跑 `_remove-cc-switch.ps1`。
- **决策**：「最大权限/全部解决/你看着办」= 少确认、修**当前任务**；删配置目录/卸载/递归清理须**另行明示确认**。保护：CC Switch、OAuth、无关 provider。
- **后果**：`maximum-permission-scope.mdc` + 三端 AGENTS 摘要。

### ADR-G004：AI 交付防踩坑（2026-06-18）

- **背景**：program1-main 未锁改动层级导致返工。
- **决策**：模糊输入先提问；每轮一个主改动类型；验收：用户故事 → 单页 → verify；产品细节进项目 memory，不堆全局 always-on。
- **后果**：`ai-delivery-anti-patterns.mdc` + `ai-project-retrospective-rules-zh.md`。

### ADR-G005：Global agent master SSOT（2026-06-22）

- **决策**：`~/.ai-workspace/memory/global-agent-master.md` 为三端行为 SSOT；各端 AGENTS/rules 薄 shim。
- **后果**：跨工具行为一处治理；repo `AGENTS.md` 仍优先于项目细节。

### ADR-G006：Windows/Codex 失败三层 + 全局装一次（2026-07-17）

- **决策**：失败必标 L1 工具 / L2 环境 / L3 项目；Office+agent tooling 只进 `AGENT_PYTHON` 全局 venv 一次；测试前 `resolve-test-runner.py`。
- **后果**：禁止每项目重装全局依赖；禁止把 L1/L2 报成项目失败。证据：`windows-agent-failure-catalog-zh.md`、`windows-failure-triage.mdc`。

### ADR-G007：Codex 历史回填采用“元数据优先 + curated 胶囊”（2026-07-29）

- **背景**：本机 Codex rollout 体量超过 400 MB，包含工具参数、重复续接、临时推断和潜在敏感信息，不适合全文进入长期知识库。
- **决策**：
  1. rollout 只读扫描事件结构、会话元数据与最终回执；`session_index.jsonl` 仅作标题索引。
  2. 只为高价值会话生成结构化 Session Capsule；禁止整段聊天 dump。
  3. 未登记目录只进入 `待确认更新/`，不得擅自新建镜像或合并到疑似后继项目。
  4. “代码/测试通过”“外部平台链路通过”“项目整体完成”分开标记。
  5. 敏感内容只统计类别，凭据、账户、客户材料和原文 withheld。
- **后果**：Codex、Cursor、Claude Code 的历史可增量回填，同时避免重复、状态升级和隐私污染。
- **证据**：`日志/Codex历史源盘点_2026-07-29.md` 与 8 份 Codex 项目胶囊。
