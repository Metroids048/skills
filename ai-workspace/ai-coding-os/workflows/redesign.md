# Redesign Workflow

Use this for UI polish, visual overhaul, layout repair, information hierarchy, and "make it better" requests.

## Gate

Before changing UI, lock:

- Target page or flow.
- Primary layer: IA or UI.
- What must not change.
- Acceptance viewport or screenshot.
- Visual direction.

## Steps

1. Inventory current screen: purpose, hierarchy, actions, states.
2. Identify the main defect: unclear flow, weak hierarchy, generic visuals, bad responsive behavior, or missing states.
3. Propose 2-3 redesign directions when the change is broad.
4. Confirm the chosen direction.
5. Implement the smallest coherent redesign.
6. Verify states and responsive behavior.
7. Run UI review.

## Do Not

- Delete useful product capability to imitate a reference.
- Change data owner during a visual pass.
- Mix a new product strategy into a UI-only round without confirmation.
