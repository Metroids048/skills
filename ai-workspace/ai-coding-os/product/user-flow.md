# User Flow

Use this to define what the user actually does before UI layout decisions.

## Flow Card

- Entry point.
- User intent.
- Required context.
- Primary action.
- System response.
- Success result.
- Recovery path.
- Next best action.

## Rules

- Prefer one complete story over isolated screens.
- Make the first step obvious.
- Preserve user context when moving across pages.
- Empty, loading, error, and success states must keep the user oriented.
- AI features must show when they are using model output, local fallback, or unavailable mode.

## Acceptance

A flow is ready when a tester can say:

"Starting from this entry, I can complete the main task and know what happened next."
