# 成本与稳定性约束（全局 · SSOT）

> Last updated: 2026-07-30  
> Applies to: Cursor / Claude Code / Codex — all projects  
> Cursor rule: `~/.cursor/rules/cost-stability-constraints.mdc`  
> Shims: `~/.claude/AGENTS.md` · `~/.codex/AGENTS.md`

适用于所有编码与运维类任务。与「最大权限」「Lean token」并存；冲突时以**用户当次明确指令**为准，其次本约束。

## 约束（必须遵守）

1. **单目标收口** — 本轮只完成已定义的唯一目标，不做非阻塞扩展与全面重构。
2. **低频轮询** — 长时间运行的测试、编译或安装，不得高频轮询；每 30–60 秒检查一次即可。
3. **日志截断** — 命令输出只读取关键错误及末尾约 200 行；禁止把完整超长日志反复送入上下文。
4. **限次重试** — 遇到 429、断流、网关错误或无响应时，最多自动重试 1 次；再次失败后立即停止，并记录恢复点。
5. **阶段提交** — 每完成一个可独立验收的阶段，立即创建 Git 提交（本条授权阶段提交，无需再逐次询问）。若用户当次明确说「不要提交」，则跳过并在恢复点注明。仍禁止提交密钥 / `.env` / Cookie。
6. **避免重复扫描** — 不重复扫描已经确认且没有变化的文件。
7. **推理分级** — 高推理仅用于根因分析与关键决策；方案确定后的实现阶段降低推理强度，按既定方案直接落地。
8. **中断恢复点** — 任务中断前必须输出：已完成内容、当前状态、未完成步骤、下一步命令、最新提交（hash/message，若有）。

## 与既有规则的关系

| 既有规则 | 关系 |
|---|---|
| Working Agreement「未要求不提交」 | 被本约束第 5 条在多阶段任务中覆盖（阶段提交） |
| Lean token / Headroom / RTK | 互补；第 3 条强化「勿灌长日志」 |
| Retry max 3（同检查修复） | 第 4 条专指 **API/网关/429/断流**；同检查修复仍按 Working Agreement |
| 验证不得省略 | 不因省成本跳过测试/验收 |
