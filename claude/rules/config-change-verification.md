# 配置变更强制验证规则（2026-07-16新增）

## 触发条件
当任务涉及修改以下内容时，本规则强制生效：
- 策略配置（bootstrap.py、策略规则）
- 风险参数（risk.py、RiskProfile）
- 交易币种（universe.py）
- 环境变量（.env）
- 数据库schema（Alembic）
- 费率/滑点假设
- 任何影响运行时行为的参数

## 强制执行步骤

### ⚠️ 步骤1-2-3是历史失误点，必须严格执行

1. **修改代码** ✅
   - 修改相关文件
   - 使用Read工具验证

2. **明确告知必须重启** ⚠️⚠️⚠️
   ```
   ⚠️ 配置修改完成，但必须重启系统才能生效！
   
   请立即执行：
   1. 运行 完全重启系统.cmd（会停止旧进程）
   2. 等待系统启动完成
   3. 运行 python scripts/verify_config.py
   4. 将验证结果告诉我
   
   ⚠️ 重要：在你确认重启并验证通过前，我不能声明任务完成。
   ```
   
   **禁止**只说"配置完成"而不提重启！

3. **等待用户确认** ⚠️
   - 明确等待用户回复"已重启"
   - 不假设用户会自行重启
   - 用户未确认前，不执行后续步骤

4. **验证数据库配置**
   - 检查数据库中的配置值
   - 与代码中的预期值对比

5. **验证运行时行为**
   - 扫描币种是否符合预期
   - 订单参数是否使用新配置
   - 拒单原因是否改变

6. **声明完成**
   - 只有所有验证通过才能说"完成"

## 历史失误案例（警示）

**案例：2026-07-16超激进配置未生效**
- **修改内容**：42%阈值、5%风险、40x杠杆、Top10币种
- **失误**：只修改了代码，创建了文档，但**没有告诉用户重启**
- **后果**：跑了一整晚，旧配置仍在运行，225个订单全部被拒
- **用户反馈**："你最近返工和失误的次数越来越多了"

**教训**：
- 代码修改 ≠ 配置生效
- 必须重启 + 验证才算交付
- 不能假设用户知道要重启

## 检查清单模板

每次配置变更复制此清单：

- [ ] 修改代码并Read验证
- [ ] 明确告知用户"必须重启"
- [ ] 提供重启命令和验证脚本
- [ ] 等待用户确认已重启
- [ ] 验证数据库配置
- [ ] 验证运行时行为
- [ ] 所有通过后声明完成

## 与现有规则的关系

本规则是"交付自查规则"的**配置变更专项扩展**：
- 交付自查规则：Read验证代码逻辑已落地
- 本规则：还需验证配置在运行时生效

两条规则叠加执行，不可省略任何一条。
