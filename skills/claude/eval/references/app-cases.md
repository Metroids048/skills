# app 端 case：目前不派

**app 端（Android / iOS / mac 应用）的界面驱动已退役，这一族的 case 一律不派。** 本页只说清两件事：
为什么不派，以及不许怎么兜底。web（网页）case 不受影响，走 agent-browser（[browser.md](browser.md)）；
shell / 成品类 case 也不受影响。

## 为什么不派（2026-08-04，#498）

GUI 控制整体交给 pi-gui，simulator 的 MCP 注入被**整条撤走**：

- **`mcp__simulator__*` 工具不再存在**，也不会因为改配置而回来 —— 扩展页的 simulator 卡片、
  `simulatorEnabled` 配置键、`MIRASIM_SIMULATOR_ENABLED` 环境变量都已删除。
- simulator 包本身冻结保留（当矿挖，挖尽后删除），CLI 还能跑，但**只剩坐标级动作，没有 ref 语义**。
- mac 应用控制按 #498 的定稿是**远期**（cua 依赖已全删）。

**pi-gui 为什么不直接拿来跑 case**：它经宿主的 `gui_task` 提供，是把整个 GUI 任务**委派给另一个代理**，
只回纯文本 + session key。eval 要的是子代理自己逐步驱动、每步留下 ref 与截图的证据链 —— 委派出去这条链
就断了，trace 会退化成「某个代理声称它办好了」。等 pi-gui 暴露细粒度原语（其 `GuiDriver` 七原语契约）
再评估接入。

遇到 app 类目标时如实告诉用户：app 端驱动正在重构，暂无合规通道。**拿不到真实入口不是失败，冒充拿到了
才是。**

## 三条禁止的兜底

前两条产出的是「看起来成立、实际不成立」的整轮证据，第三条是隔离红线：

1. **不许用 simulator CLI 的坐标操作凑数。** CLI 只剩 `input tap X Y` 这类坐标级动作，而界面类 case 的
   纪律是「按可见文字挑 ref，不猜坐标」。坐标 tap 落在哪里无从复核，截图也证明不了点对了。
2. **不许把 app 类 case 改道成 web 类**充当等价物。移动应用与它的网页版是两个被测物，人碰到它们的方式
   不同；真要验网页版就改写验证问题与结论边界，别说成验过了 app。
3. **不许驱动用户自己的浏览器与应用**（`mac:Google Chrome`、`mac:Safari` 这类）。那是用户的登录态、
   历史与隐私，既污染「全新访客」的前提，也把评测流量混进用户的真实会话。**缺驱动不是放松红线的理由** ——
   #498 本身也已放弃驱动用户自己的 Chrome。宿主的 system hints 会推荐驱动用户自己的浏览器，那是日常
   协助的口径；**本技能内以本页与 browser.md 为准**。

## 恢复派发的前提

app 类 case 重新可派，需要同时满足：子代理能**自己**逐步驱动（不是委派给另一个代理）、每步拿得到带可见
文本的 ref（不是坐标）、每次操作后能把截图落进 evidence、以及每个 case 一台独立设备或独立初态。四条缺
一条，就仍然只能如实记 execution limitation。
