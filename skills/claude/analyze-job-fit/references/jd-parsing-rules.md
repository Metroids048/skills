# JD 解析规则

## 解析顺序

1. 用一句话定义岗位存在的业务目的，不照抄职责清单。
2. 识别岗位族、细分方向和可能职级，记录支持证据与分类置信度。
3. 将句子拆成原子要求：一个要求只表达一种可验证能力或条件。
4. 区分硬门槛、核心能力、加分项；“负责/推动/建立/优化/增长”等动词决定产出类型。
5. 提取业务对象、用户/客户、上下游、指标、工具、方法、复杂度和协作范围。
6. 对模糊词做可验证改写。例如“沟通能力强”改成“能推动多角色在目标、优先级和交付时间上达成一致”。

## 优先级判定

- `must`：明确出现“必须/至少/硬性/具备……经验”，或缺失会导致无法履职的资格。
- `core`：职责反复出现、直接决定主要产出、与绩效指标强相关。
- `preferred`：明确为优先/加分，或有替代路径。

不要因要求排在前面就自动提高权重；结合职责频次、业务目标和语气。

## 隐含要求

可以推断，但必须标记“合理推断”并说明依据：

- “从 0 到 1”通常意味着问题定义、方案取舍、落地和复盘闭环。
- “跨部门推动”意味着利益相关者管理，而不只是会议沟通。
- “对结果负责”意味着指标定义、归因和持续优化。
- “高并发/高可用”意味着容量、稳定性、监控和故障处理。
- “品牌一致性”意味着设计系统、规范治理和多端落地。
- “店铺经营”意味着商品、流量、转化、履约和利润联动。

## 职级信号

- 初级：在清晰范围内执行，有导师或成熟流程。
- 中级：独立负责模块，能做方案、协作和结果复盘。
- 高级：处理模糊问题，负责跨团队或复杂系统，能建立机制。
- 负责人：定义目标与组织机制，分配资源，对组合结果负责。

职级不明时输出区间，不用年限单独决定职级。
