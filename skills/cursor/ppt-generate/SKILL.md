# ppt生成

## 任务定位

这类任务不是“把资料塞进 PPT”，而是把用户给定的业务材料转成可汇报、可投屏、可编辑、贴近指定模板气质的演示文稿。

核心目标是一次性交付可用稿：内容来源准确，视觉模板明确，页面节奏紧凑，文字不溢出，图片/表格/流程图/架构图经过真实预览验收。

## 详细需求规格

### 1. 先分清三类输入

- **视觉模板**：决定标题长度、字号层级、色板、页眉页脚、表格样式、流程图/架构图语言。
- **内容来源**：决定业务事实、数字、功能、口径、风险、待确认项。
- **用户手改稿/最终认可稿**：优先作为审美和取舍样板，不得被脚本重新覆盖。

若用户没有明确三者，先用通俗语言确认：

- “这份 PPT 是只做视觉参考，还是内容也要沿用？”
- “最终是基于你手改稿继续修，还是另起新版本重做？”
- “希望页数保持、扩页，还是压缩到更适合汇报？”

### 2. 版本和文件规则

- 新建版本，不覆盖用户认可或手动修改过的文件。
- 文件名必须带版本号，如 `V0.6.1`、`V0.7`；配套生成同版本大纲、自检报告、预览目录。
- 若发现 `~$xxx.pptx` 锁文件，说明 PPT 可能正在打开；复制新版本再改。
- 中文 Markdown 用 UTF-8；中文路径/Office 文件优先按本机 Windows Agent Shell 规则处理。
- PowerPoint 文件要尽量保持可编辑：流程图、架构图、矩阵、表格优先用原生形状和文本，不把整页做成截图。

### 3. 模板复刻标准

- 抽取或人工观察模板的这些要素后再动手：
  - 标题字号、正文字号、表格字号、页脚字号。
  - 主色、强调色、浅色块、边框和线条粗细。
  - 标题是否短、是否有副标题、是否有章节隔页。
  - 表格是普通网格、分组表、矩阵表、色带表还是图表结合。
  - 流程图/架构图用直箭头、粗箭头、分层块、泳道、矩阵还是时间轴。
- 不允许只做到“字体统一”。必须做到模板的字号层级、留白比例、颜色层次和图形语言接近。
- 内容可以与模板区分，视觉语言要贴模板；不要照搬模板里的无关内容或空壳页面。

### 4. 字号和标题标准

- 默认按模板字号；若模板未明确，投屏汇报建议：
  - 页标题：32-44pt，短标题优先。
  - 章节页标题：48-60pt。
  - 正文/表格主文字：12-18pt。
  - 图内标签：不低于 10-12pt。
  - 页脚/页码可小于正文，但不得干扰阅读。
- 标题要像汇报标题，避免“长句 + 冒号 + 解释”。
- 除非模板本身有副标题，否则不要给每页加副标题。
- 标题过长时先改写，不要靠缩小字号硬塞。

### 5. 页面节奏和页数

- 不为凑页数扩页。内容不足的页面要合并、删除或转为更高密度图表。
- 空章节页、只有编号/章节名/标签的过渡页，除非模板强制要求，否则删除。
- 一页只讲一个主结论，但必须有足够信息密度：图、表、关键数字、流程节点或明确结论至少占其一。
- 扩页的前提是字号可读、内容足够；压缩的前提是不牺牲关键业务逻辑。

### 6. 表格、流程图和架构图

- 表格不能是默认网格。至少要有：
  - 深色或模板色表头。
  - 首列/分组列层级。
  - 重点项、风险项或待确认项强调色。
  - 合理行高，文本不贴边不出框。
- 流程图不能只是小字卡片串联。至少检查：
  - 箭头方向清楚。
  - 节点文本短。
  - 关键节点用红色/强调色。
  - 线条和箭头粗细接近模板。
- 架构图优先用分层、泳道、矩阵或“用户端/能力层/应用端/数据底座”等结构，不堆普通矩形。

### 7. 图片和截图

- 图片应承载真实信息，能放大就放大；不要小图漂在大片空白里。
- 截图要裁掉无关边缘，保持比例，不拉伸变形。
- 如果图片是业务证据或模板素材，旁边文字要让位，不能把图压成装饰。
- 图片页导出后必须肉眼确认图中文字是否可读。

### 8. 不确定项表达

- 业务冲突、接口、权限、公式、周期等未确认内容必须保留 `[待确认]`，不能伪装成已确定。
- 但领导汇报主线里不要过早放大内部不确定项；适合放在风险/待确认/下一步确认页统一收口。
- Mock、兜底、演示数据等字眼只在需要说明边界时出现，不要让正式汇报页像内部研发备注。

## 硬性检查清单

- [ ] 已明确视觉模板、内容来源、用户手改稿三者各自作用。
- [ ] 未覆盖用户手动修改或已认可的 PPT，已另存新版本。
- [ ] 标题短而像模板；没有无必要副标题；没有长解释型标题。
- [ ] 页数与内容密度匹配；没有低价值空页、纯章节页或“凑页数”页面。
- [ ] 正文、表格、图内标签按模板字号层级设置；没有靠极小字号塞内容。
- [ ] 导出 PNG 后逐页看过；未发现文字出框、压线、被箭头/色块遮挡。
- [ ] 图片和截图已尽量放大；没有小图漂浮和大片无意义留白。
- [ ] 表格有表头、分组、重点色和足够行高，不是默认素表。
- [ ] 流程图/架构图/箭头贴近模板语言，方向清楚，节点文字短。
- [ ] 关键数字、功能点、业务事实来自指定资料，未擅自编造。
- [ ] `[待确认]` 保留在合适位置，不在主线里制造不必要的不确定感。
- [ ] PPTX、大纲、自检报告、PNG 单页预览、contact sheet 同版本、同口径。
- [ ] 自检报告包含视觉验收结论，而不只是页数、字体、关键字统计。
- [ ] 若 PowerShell/编码/Office COM 出现异常，已区分“终端显示问题”和“文件本体问题”。

## 标准产出模板

每次交付至少包含：

- `项目名-主题-Vx.y.pptx`
- `项目名-主题-Vx.y-大纲.md`
- `项目名-主题-Vx.y-自检报告.md`
- `tools/ppt_vxy_build.py` 或等价可复现生成/修订脚本
- `tools/ppt_vxy_preview/`：每页 PNG 和 `contact_sheet.jpg`

自检报告必须包含：

- 基础结构：页数、版本、文件是否可解析。
- 模板对齐：标题、字号、配色、表格、流程图/架构图是否贴近模板。
- 视觉问题：逐页预览后是否发现溢出、遮挡、留白失衡、图片过小。
- 内容口径：关键数字/术语/待确认项是否完整。
- 未验证项：没有真实打开 PowerPoint 或未做人工逐页检查时必须说明。

## 执行工作流

1. **读规则和材料**：先读项目/用户规则、全局记忆、PPT 相关 skills、用户给定模板和资料目录。
2. **确认可变参数**：锁定视觉模板、内容来源、页数目标、版本策略、汇报对象、是否基于手改稿。
3. **抽取模板事实**：统计或观察模板字号、颜色、标题长度、表格/流程/架构样式；不要凭感觉。
4. **做页面大纲**：先定页数和每页主结论；删掉空章节页和低价值过渡页。
5. **生成或修订 PPTX**：优先使用可编辑原生 PPT 形状；不要覆盖旧版。
6. **生成配套文件**：同步输出大纲、自检报告、预览目录和 contact sheet。
7. **自动校验**：检查页数、字体、关键口径、媒体数量、文件可解析。
8. **视觉验收**：打开 contact sheet 和高风险单页 PNG，逐页检查文字、图片、表格、流程、留白。
9. **回补问题**：发现出框、空、素、小、长标题、图太小，回到源脚本或副本修正后重新导出。
10. **交付说明**：明确使用哪个版本，说明验证证据和仍需用户人工快扫的风险。

## 需要向用户确认的可变参数

- 视觉模板：哪份 PPT 只作为视觉模板。
- 内容来源：哪些文档/Excel/PDF/PPT 是事实来源。
- 最终样板：用户手动改过的哪一版算认可稿。
- 版本策略：覆盖、另存、复制手改稿后改。
- 页数目标：保持、压缩、扩展或按内容自适应。
- 汇报对象：领导、甲方、技术评审、内部研发。
- 标题风格：是否允许副标题，标题应偏业务结论还是技术描述。
- 待确认项位置：主线展示还是统一放风险页。
- 最低字号：正文、表格、图内标签、页脚分别多少。
- 输出格式：只要 PPTX，还是同时要大纲、自检、PNG 预览。

- 不以 `V0.7` 作为最终样板；它只提供“删空页、压标题”的教训，不代表用户认可的最终视觉质量。
